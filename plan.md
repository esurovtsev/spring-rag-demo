# Stateless RAG App with Spring AI: Project Plan

## Notes
- Stateless RAG pattern: Retrieve (vector search) + Generate (LLM)
- No conversation history is stored; each query is processed independently
- Embeddings must be generated by the app (not the vector DB)
- Qdrant chosen for vector storage (open-source, Docker-friendly, Spring AI support)
- OpenAI `text-embedding-3-small` for embeddings, `gpt-4o-mini` for LLM
- REST API is the primary interface; optional UI via Swagger or simple frontend
- Project will be initialized using Spring Initializr (in existing 'spring-rag-demo' folder, Java 21)
- Base package will be `com.grabduck.springrag`
- Project will be demoed on YouTube (GrabDuck) and used as a portfolio reference
- Introduce a `service` package for coordinating RAG workflow, maintaining separation of concerns
- RAG demonstration will use Amazon Return Policy content; a static JSON file will be included in the project and loaded into the vector store at startup if empty (pre-populated data approach)
- The API will include a feature toggle (request param) to enable/disable RAG (default: on) for comparison purposes
